# 익일 시간대별 주차 혼잡도 예측과 일별 평가

## 운영 일정 — 한국시간

| 시각 | 위치 | 작업 |
|---|---|---|
| 매 10분 | 서버 | 주차 관측 수집. 17:10도 포함 |
| 17:05 | 서버 | 기존 익일 승객예고 기준본 수집 유지 |
| 17:10 | 서버 | 추가 익일 승객예고 기준본 수집. 값이 같아도 새 배치를 저장 |
| 09:00·로그인 | 로컬 | 기존 증분 동기화 유지 |
| 17:10 | 로컬 | 추가 증분 동기화 |
| 17:15 | 로컬 | 다시 증분 동기화 → 전체 CSV 조립 → 익일 24시간 예측 |
| 00:10 | 로컬 | 증분 동기화 → 전날 날짜의 완료된 예측 평가 |

서버 17:10 수집과 로컬 동기화가 동시에 시작할 수 있으므로 17:15 예측 직전에도 동기화합니다. 예측·평가 작업은 최근 동기화 여부와 무관하게 매번 신규 행을 확인합니다.

예: 10월 9일 17:15에 10월 10일 00~23시를 예측하고, 10월 11일 00:10에 10월 10일 실제값과 비교합니다. 17:15 예측 작업은 과거 예측 평가를 실행하지 않습니다.

## 등록과 확인

```powershell
.venv\Scripts\python.exe scripts\register-server-1710.py --config local-work/server-sync.json
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\register-daily-analysis.ps1
Get-ScheduledTaskInfo -TaskName AirportParking-NextDayPrediction
Get-ScheduledTaskInfo -TaskName AirportParking-NextDayEvaluation
Get-Content logs\daily-analysis.log -Tail 30
```

등록 스크립트는 기존 수집·09:00 동기화 작업을 보존합니다. 서버 cron은 `local-work/cron-backups/`에 백업한 뒤 관리 표시가 붙은 17:10 작업 한 줄을 등록합니다. 서버와 로컬 시간대는 각각 Asia/Seoul, Korea Standard Time이어야 합니다.

Windows 작업은 기존과 같이 로그인 계정으로 실행합니다. PC가 꺼져 있거나 로그아웃 상태면 정시에 실행할 수 없습니다. 사용 가능한 다음 시점에 실행하도록 설정하고 절전 깨우기도 요청하지만, 전원이 꺼진 PC를 켜지는 못합니다. 다음날 오전으로 밀린 예측은 실행하지 않습니다. 당일 17:15 이후 지연 실행은 17:15까지 확보된 정보로 재현합니다. 00:10 평가를 놓치면 다음 실행 때 아직 평가하지 않았거나 관측이 부족했던 과거 완료 날짜도 평가합니다.

## 예측 정의

- 대상: 다음날 한국시간 00:00~23:00, 운영 중인 주차장별 24행. 현재 19구역이면 456행입니다.
- 각 행에 **시간대 평균·최대·최소 혼잡률**을 각각 예측합니다.
- 혼잡률은 관측 주차 대수/당시 주차면수입니다. 100% 초과를 보존하고 `최소 ≤ 평균 ≤ 최대`를 적용합니다.
- 예상 주차 대수는 발행 시점 면수를 사용한 평균 혼잡률의 환산값입니다. 다음날 면수가 바뀌는 경우 이 추정 조건을 확인해야 합니다.
- 최대·최소 실제값은 10분 주기 등의 **수집된 관측에서의 최대·최소**입니다. 관측 사이의 연속적인 실제 극값은 알 수 없습니다.

## 입력과 미래 정보 제외

17:15까지 수집한 관측만 사용합니다. 주차 관측은 20분 이내의 최근값이어야 하고, 승객예고는 당일 **17:10~17:15에 수집한 D+1 전체 배치**가 필요합니다. T1/T2 입국·출국 × 24시간 96행이 모두 있어야 합니다. 불완전하거나 오래된 입력이면 실패 상태로 종료합니다. 다음에 확보한 수정 예고를 이전 발행의 입력으로 바꾸지 않습니다.

입력 변수는 주차장·종류·터미널, 최근 혼잡률과 면수, 예측까지 남은 시간, 시간대·요일, 예측 시점에 이미 알 수 있는 전일·전주 같은 시간의 평균·최대·최소, 익일 입출국 예고, 주변 시간대·누적·일별 합계입니다. 다음날 예측할 때 실제로 확보할 수 없는 당일 저녁 관측이나 이후 수정 예고는 제외합니다.

## 모델 선택과 데이터 부족

현재값 유지, 전주/전일 동일 시간 기준, Ridge, Random Forest를 비교합니다. 학습 모델은 평균·최대·최소를 함께 예측합니다. 검증 MAE 세 값의 동일 가중 평균으로 모델을 선택하고 마지막 테스트 날짜는 선택에 사용하지 않습니다.

서로 다른 완료 대상 날짜가 최소 28개(학습 14일 이상, 검증 7일, 테스트 7일) 필요합니다. 날짜 순으로 분리하고 검증·테스트 발행 시점에 아직 확보하지 못한 앞 구간 정답을 제외합니다. 데이터가 부족하면 전주·전일 같은 시간, 현재 혼잡률 순으로 사용 가능한 기준값을 사용하고 `prediction_kind=baseline`을 표시합니다. 충분한 날짜 수만으로 성능을 보장하지 않으며 평가 결과와 기준 예측 대비 개선을 확인해야 합니다.

## 평가 기준

- 정답은 시간대별 고유 관측의 평균·최대·최소 혼잡률입니다.
- 한 시간에 서로 다른 10분 구간 4개 이상의 관측이 있어야 합니다. 중복 관측으로 이 조건을 채우지 않습니다.
- 시간이 끝났고 평가 시점까지 수집된 관측만 정답으로 사용합니다.
- 미도래 시간은 `pending`, 관측이 부족한 완료 시간은 `missing`입니다. 누락을 0으로 처리하지 않습니다.
- 평균·최대·최소마다 MAE(%p), RMSE(%p), 90% 이상 여부 F1, 주차장별·시간대별 오차를 기록합니다.
- 전체 예측 중 비교 가능한 비율(`coverage_pct`)을 함께 기록합니다. 누락 있는 완료일은 이후 실행에서 다시 평가할 수 있습니다.
- 예측 원본은 재학습하거나 평가할 때 덮어쓰지 않습니다. 완전하게 평가된 과거 날짜는 반복 계산하지 않습니다.

## 실행과 결과

```powershell
.venv\Scripts\python.exe -m airport_parking.daily_analysis predict
.venv\Scripts\python.exe -m airport_parking.daily_analysis evaluate
```

예측을 17:15 전에 수동 실행하면 `skipped_before_cutoff`로 종료합니다. 결과는 Git 제외 경로 `data/processed/next-day/발행일/`에 보관합니다.

| 파일 | 내용 |
|---|---|
| `predictions.csv` | 다음날 주차장별 시간대별 평균·최대·최소 예측과 사용한 입력 |
| `manifest.json`, `report.md` | 발행 마감, 대상 날짜, 승객예고 배치, 입력 데이터와 모델 상태 |
| `metrics.json`, `model.pkl` | 학습 준비·검증·테스트 결과와 선택된 모델 |
| `training_examples.csv`, `backtest_predictions.csv` | 있을 때 저장하는 학습 사례와 테스트 구간 예측 |
| `evaluation.csv`, `evaluation.json` | 00:10 작업이 작성하는 실제값과 세 통계량별 평가 |

루트의 `latest.json`, `last_prediction_job.json`, `last_evaluation_job.json`으로 최근 결과를 확인합니다. 오류는 `logs/daily-analysis.log`에 기록하며 예약 작업 결과가 0이 아니면 로그를 확인합니다.
