# 로컬 수집 일정 (한국시간)

## 운영 기간

- 시작: 2026-09-30 21:50 주차 수집. 승객예고 첫 예약 실행은 같은 날 23:05.
- 마지막 예약일: **2026-10-08 목요일 포함**. 이후 실행 트리거가 없습니다.
- Windows 작업 스케줄러에 등록된 작업은 기간이 끝난 뒤에도 목록에 남지만 다시 실행되지 않습니다.
- 로컬 PC가 켜져 있고 현재 Windows 사용자가 로그인한 상태에서 실행됩니다. 절전·종료·로그아웃 중 놓친 실행은 소급 수집되지 않습니다.

## 주차 현황

- 작업 이름: `AirportParking-Parking-10min`
- 매 10분 정각(00, 10, 20, 30, 40, 50분) 실행
- 명령: `airport-parking collect`
- API 관측 시각과 주차구역을 고유 키로 사용하므로 같은 관측값은 중복 저장하지 않습니다.

## 승객예고

현재 API에서 확인된 범위는 오늘(D)과 내일(D+1)입니다. `selectdate=2`를 17시 이후 호출해도 오늘 데이터가 반환되어 D+2 수집은 사용하지 않습니다.

| 실행 시각 | 작업 이름 | 조회 날짜 | 목적 |
| --- | --- | --- | --- |
| 11:05 | `AirportParking-Forecast-1105` | 당일(D) | 전날 17:05 기준 예고의 변경 확인 |
| 17:05 | `AirportParking-Forecast-1705` | 다음 날(D+1) | 다음 날의 기준 예고 저장 |
| 23:05 | `AirportParking-Forecast-2305` | 다음 날(D+1) | 같은 예고의 변경 확인 |

17:05에는 기준본을 항상 저장합니다. 23:05와 11:05에는 마지막으로 저장한 같은 대상 날짜의 예고와 96개 시간대·터미널·방향 값을 비교하고, **값이 모두 같으면 DB에 새 버전을 만들지 않습니다**. 값이 하나라도 다르면 변경된 값의 개수를 기록하고 전체 새 버전을 저장합니다. 전체 버전을 보관해야 예측 시점에 볼 수 있던 예고를 복원하기 쉽습니다.

## 예상 호출량과 데이터량

이번 등록의 예정 실행 횟수는 다음과 같습니다.

| 항목 | 예정 API 호출 | 새 DB 행 예상 |
| --- | ---: | ---: |
| 주차 현황 | 1,165회 | 최대 약 22,135행 (최근 응답의 19개 주차구역 기준) |
| 승객예고 | 25회 | 기준본만 저장될 때 약 768행, 모든 확인에서 바뀌면 최대 2,400행 |

승객예고는 호출당 대상 날짜의 24시간 × 터미널 2개 × 입출국 2개 = 96행입니다. 주차 데이터는 API가 같은 관측 시각을 여러 번 돌려주면 중복 방지 때문에 예상보다 적게 저장됩니다. JSON 원본과 인덱스를 포함한 디스크 사용량은 **수십 MB 수준 이하**로 예상하지만, 실제 크기는 DB에서 확인해야 합니다. PostgreSQL 자체 파일과 Docker 볼륨의 기본 크기는 이 추정에 포함하지 않았습니다.

## 실행 결과와 관리

- 실행 로그: `logs/parking-YYYYMMDD.log`, `logs/passengers-YYYYMMDD.log`
- 작업 상태: Windows 작업 스케줄러에서 위 작업 이름으로 조회
- 조기 중지: 작업 스케줄러에서 네 작업을 모두 **사용 안 함**으로 변경
- 일정 재등록: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/register-local-schedule.ps1`

주차 API는 개발 계정 일 1,000회 한도로 안내되어 있습니다. 이 일정의 정상적인 주차 호출은 하루 144회입니다. 승객예고도 정상적인 하루 3회입니다. 재시도가 발생하면 실제 호출 수가 약간 늘어날 수 있습니다.
