# 운항·공휴일을 사용하는 익일 예측 및 평가

로컬 `airport_parking.daily_analysis`에 연결했습니다. 매일 17:15 예측, 매일 00:10 전일 날짜 평가의 기존 예약 명령이 변경된 코드를 사용합니다. 서버는 수집만 수행합니다.

## 입력

- 공휴일 여부, 공휴일 전날·다음날 여부, 주말을 포함한 휴일 여부
- 터미널별 시간대 도착·출발 편수, 결항 편수
- 도착 직전 2시간·출발 이후 2시간 편수(예측 대상 날짜 안의 시간만)
- 시간대 누적 편수, 하루 전체 편수
- 각 서비스 입력의 가용성, 선택한 스냅샷 ID와 수집 시각

공식 [터미널 코드 설명](https://www.data.go.kr/data/15095068/openapi.do)에 따라 P01(제1터미널)·P02(탑승동)를 T1, P03(제2터미널)을 T2 주차장에 연결합니다. 운항 편수는 `masterflightid` 또는 `flightId`와 예정일시를 기준으로 코드셰어 편을 합치며 Master 행을 우선합니다. 결항은 운항 편수에서 제외하고 별도 변수로 보존합니다. 예정일시 기준으로 시간대를 집계합니다.

## 과거 정보만 사용

학습·예측 모두 각각의 발행일 17:15 이전에 수집된 스냅샷만 선택합니다. 운항 일정은 해당 익일 날짜·방향의 최신 자료이며 발행 마감 기준 12시간 이내 수집분만 사용합니다. 공휴일은 해당 연도·월의 최신 자료를 사용합니다. 수집 시작일 이전의 과거 공휴일 자료도 나중에 수집한 달력으로 소급 채우지 않습니다.

서비스의 당시 자료가 없으면 가용성은 0, 편수·공휴일 값은 결측값입니다. ‘조회했고 0건’과 ‘자료 없음’을 구분합니다. 이전 형식의 데이터셋도 그대로 읽을 수 있으며 누락은 로그와 보고서에 표시합니다. 평가할 때 미래 운항 변경본을 다시 끼워 넣지 않고 발행 시 저장한 입력을 그대로 사용합니다.

## 학습과 모델 선택

기존 현재값·전일/전주 기준 모델, Ridge, Random Forest를 유지합니다. 학습·검증·테스트 구간에서 세 서비스(공휴일·도착·출발) 자료를 모두 갖춘 날짜가 각각 최소 14·7·7일이면 `ridge_context`, `random_forest_context` 후보를 추가합니다. 기존 학습 모델은 기존 입력만, 새 후보는 기존+운항+공휴일 입력을 사용합니다.

모든 후보는 동일한 날짜 분할과 동일한 평균·최대·최소 혼잡률 정답으로 비교합니다. 검증 구간의 세 MAE 평균이 가장 작은 모델을 선택하고, 테스트 점수는 선택 이후 별도로 기록합니다. 새 입력 모델이 자동으로 우선 선택되지는 않습니다. 데이터가 부족한 동안에는 기존 기준 예측을 유지하며 새 입력과 사용 여부를 저장합니다. 따라서 입력 연결 완료가 정확도 향상 검증 완료를 의미하지 않습니다.

## 결과 확인

`data/processed/next-day/<발행일>/`:

- `predictions.csv`: 새 변수, 원본 스냅샷 ID·수집 시각, `context_used_by_model` 포함
- `manifest.json`: `feature_schema_version=2`, 예측 입력 가용성과 실제 모델 사용 여부
- `metrics.json`: 입력 가용성, 새 모델 준비 상태, 날짜 분할, 후보별 검증·테스트 점수
- `backtest_predictions.csv`: 학습 검증이 가능한 경우 후보별 평균·최대·최소 예측
- `evaluation.json`: 기존 세 정답의 MAE/RMSE 등과 공휴일·휴일·자료 가용성별 평가
- `evaluation.csv`: 발행 입력과 실제 정답 및 오차

이전에 발행한 예측을 덮어쓰지 않습니다. 새 입력의 효과를 확인하려면 새 모델이 선택된 이후의 실제 익일 정답과 누적 백테스트 결과를 확인해야 합니다.
