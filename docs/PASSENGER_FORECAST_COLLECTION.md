# 인천공항 승객예고 수집 및 주차 혼잡도 분석 설계

## 데이터 출처와 의미

- 공식 API: [인천국제공항공사_승객예고-출·입국장별](https://www.data.go.kr/data/15095066/openapi.do)
- 데이터 ID: `15095066`
- 실제 호출 경로: `https://apis.data.go.kr/B551177/passgrAnncmt/getPassgrAnncmt` (2026-09-30 인증된 응답으로 확인)
- 대상: T1·T2 출국장 및 입국장의 시간대별 **예상 승객 수**
- 조회 범위: 오늘(`selectdate=0`)과 내일(`selectdate=1`)
- 개발 계정 호출 한도: 하루 1,000회. 활용신청은 주차 정보 API와 별도로 진행해야 합니다.
- 시간대: `adate`(날짜)와 `atime`(한 시간 구간)을 한국시간으로 해석해 DB에는 시간대 포함 시각으로 저장합니다.

이 값은 실제 공항 이용객 실적이 아니라 공항이 제공하는 **승객예고**입니다. 주차 혼잡도를 미리 예측할 때 사용할 수 있는 입력값입니다. 실제 이용객 수가 필요한 분석은 별도 실적 데이터 출처를 찾아야 합니다.

## 수집 단위

API 응답의 각 시간대에서 다음 합계 필드를 저장합니다.

| 터미널 | 방향 | API 필드 |
| --- | --- | --- |
| T1 | 입국 | `t1egsum1` |
| T1 | 출국 | `t1dgsum1` |
| T2 | 입국 | `t2egsum1` |
| T2 | 출국 | `t2dgsum2` |

DB의 `passenger_forecast_batches`에는 호출 시각과 원본 JSON을, `passenger_forecasts`에는 시간대·터미널·방향별 예고 인원을 저장합니다. 실제 응답에는 하루 24개 시간대 행과 별도의 `합계` 행이 포함됩니다. `합계` 행은 원본에만 보존하고 시간별 테이블에는 넣지 않습니다. 같은 목표 시간에 대한 예고가 나중에 바뀔 수 있으므로 이전 예고도 삭제하지 않습니다.

## 실행

1. 공공데이터포털에서 이 API의 활용신청을 완료합니다.
2. 기존 공공데이터 서비스키를 그대로 사용할 수 있다면 `.env`의 `AIRPORT_PARKING_SERVICE_KEY`를 사용합니다. 별도 키를 쓸 경우 `AIRPORT_PASSENGER_SERVICE_KEY`를 설정합니다.
3. PostgreSQL이 실행 중인 상태에서 다음을 실행합니다.

```powershell
uv run airport-parking collect-passengers
```

저장 결과 확인:

```sql
SELECT f.target_hour, f.terminal, f.direction, f.expected_passengers, b.fetched_at
FROM passenger_forecasts AS f
JOIN passenger_forecast_batches AS b ON b.id = f.batch_id
ORDER BY b.fetched_at DESC, f.target_hour, f.terminal, f.direction
LIMIT 20;
```

## 주차 혼잡도 예측에 연결할 때

1. `parking_observations.observed_at`을 시간 단위로 맞추고, 주차구역을 T1 또는 T2에 매핑합니다.
2. 해당 시간의 T1/T2 입국·출국 예상 인원을 입력 변수로 사용합니다. 주차 대수 또는 `occupied_spaces / total_spaces`를 목표값으로 둡니다. `total_spaces=0`인 미운영 구역은 제외합니다.
3. **주차 관측 시각보다 먼저 수집된 승객예고만** 사용합니다. 예를 들어 3시간 전 예측 모델이라면 관측 시각보다 3시간 이상 먼저 확보한 예고를 선택합니다. 이후에 수정된 예고를 학습 데이터에 넣으면 미래 정보를 미리 본 것처럼 되어 성능 평가가 왜곡됩니다.
4. 요일·공휴일·시간대·주차장 종류 등의 변수를 추가할 수 있습니다. 주차장별 입국/출국 영향과 선행 시간을 데이터가 쌓인 뒤 비교합니다.
5. 학습·검증 데이터를 시간 순서로 나누고, 실제 운영 시점에 알 수 있는 값만 입력으로 사용합니다.

첫 DB 조회에서 목표 시간 범위는 한국시간 2026-09-30 00:00부터 2026-10-01 23:00까지였습니다. 각 T1/T2 입국·출국 조합에 48행씩 저장됐습니다. 주차 현황은 별도로 수집되므로, 모델 학습에는 두 데이터가 함께 누적된 기간이 필요합니다.

로컬 임시 일정은 [로컬 수집 일정 문서](LOCAL_COLLECTION_SCHEDULE.md)에 있습니다. 실제 API에서 `selectdate=2`는 D+2를 반환하지 않아, 17:05·23:05에는 D+1을 조회하고 다음 날 11:05에는 D를 조회합니다. 값이 그대로인 변경 확인 응답은 새 배치로 저장하지 않습니다.
